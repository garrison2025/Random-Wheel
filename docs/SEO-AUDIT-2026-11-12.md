# NumberSpinner.com｜正式站 SEO 源码与发布审计

**日期：2026-11-12｜网站：** https://numberspinner.com/  
**依据：** 项目 V1.2 执行方案、GitHub main 源码、公开 Google Search Central 与 Cloudflare Pages 文档。  
**重要边界：** 用户已确认正式域名 Active、网站可访问；本次审计的外部 HTTP / DNS 工具未能获取站点响应。**不能因此判定网站宕机，也不能把源码检查写成实时 HTTP/GSC 通过。** 用户明确要求不做邮箱收发检查。

## 1. 结论

**工程 SEO 基础较完整，索引发布门槛清楚，但尚不能宣布实站 SEO 全部通过。**

### 优点（源码已核实）
- Astro 静态 HTML；8 个首发工具/用途入口 + 5 个支持页共 13 个拟索引 URL，另 13 个候选 URL 明确暂缓索引。
- 16 个独立数字范围配置，每个有具体标题、description、H1、用途与默认数字池；首发 6 个数字范围标题没有发现相互重复。
- 官方域名默认 `https://numberspinner.com`，站点名称 `Number Spinner`；首页/数字工具/范围/其他支持页均可直接通过语义化 `<a href>` 链接访问。
- 全局索引由 `PUBLIC_INDEXABLE === 'true'` 控制；官方域名下，通过白名单输出规范 Canonical 与 Sitemap，13 个候选保留 noindex。
- 无需后端用户数据库或 API 即可实现随机选择；权重、批量抽取、导入、保存和分享有基本功能测试。
- 站点包含关于、隐私、条款、联系等可信度页面。

### 本轮实际修复，已提交 main
1. **P0 Soft 404：** 原仓库没有 `404.html`。Cloudflare Pages 在缺少顶层 404 时可能对不存在的路径使用 SPA 入口回退。本轮新增 `src/pages/404.astro`，并在 `scripts/audit-pages.mjs` 和 `scripts/audit-live.mjs` 检查文件存在、noindex、无 canonical、线上真正 HTTP 404。
2. **P1 网站名称识别：** 为正式站首页添加 Google 推荐的 `WebSite` JSON-LD（`name: Number Spinner`，`url: https://numberspinner.com/`），并添加 `og:site_name`。正式构建静态审计现在校验首页 Schema，实站验收脚本也会核查。
3. **P1 字体连接：** 两套 Google Fonts 外部字体在源码中使用 `@import`；增加对应 `preconnect`，属于减少潜在连接开销的代码优化，**不是已测量 LCP 提升**。
4. **P2 元数据质量：** 数字转盘标题缩短并保持 `Random Number Wheel Generator` 关键词；About 标题去掉重复品牌后缀。
5. **回归：** 新增 `tests/seo-launch.e2e.spec.ts` 验证预览 noindex、未知 URL HTTP 404 和暂缓索引页面。

## 5. 验收和后续观察顺序

1. Cloudflare Pages Production 确认 `PUBLIC_INDEXABLE=true` **并有成功重建**；`PUBLIC_SITE_URL` 代码已有官方域名默认值，非必填。
2. 在 GitHub Actions 手动运行 **Official domain audit**，该流程调用 `npm run audit:live`，包含 26 页面、robots、sitemap、Canonical、重定向与 404；任何失败的日志必须核实。
3. 在 GitHub Actions 跑 **Quality checks**，要求类型、Vitest、预览构建、正式索引构建、13 候选页面索引闸门和 Playwright 回归全部通过。
4. GSC 使用 `numberspinner.com` Domain property；提交 `https://numberspinner.com/sitemap.xml`；对首页、通用数字页、`1-3`、`1-5`、`1-100` 做 URL Inspection。
5. 使用 Google PageSpeed Insights 的移动端/桌面报告；为首页、通用数字页、`1-100` 建立 LCP / INP / CLS 基线。没有数据时标为 **未验证** 而非“达标”。
6. 在正式上线并验证 GSC 后，从上线日开始开展 30/60/90 天诊断；以美国非品牌查询、索引状态、页面曝光、点击和竞品 SERP 为依据做增页、合并或补功能决策。

## 6. 本次审计证据等级

- **确认：** GitHub 已读取的源码、配置、发布白名单、候选状态和已提交的修复。
- **计划而未执行：** CI/E2E 跑完、Cloudflare 正式站 HTTP 状态、结构化数据线上识别和 Core Web Vitals。
- **未提供：** GSC 实际索引/点击/曝光、浏览器实测 Lighthouse、官方域名 www/Pages redirect headers。
- **不纳入：** 邮箱收发测试（用户明确排除）。

**重要结论：不要因为新站已 Active 而宣布 SEO 已完成；也不要因为缺少 GSC 数据就把搜索表现记为 0。最关键的待核验项是实际 Production noindex/robots 设置和真实 HTTP 404/301。**
